# 自己的主題：中文稿→旁白→有聲書／Podcast用的音檔

不一定要做公版推理。喜歡的主題（讀書筆記、旅行、歷史、自己寫的故事、整理過的知識）都可以照同一條線做成「能在開車或睡前聽」的內容

## 跟推理翻譯版差在哪
| 步驟 | 公版推理 | 自己的主題 |
|---|---|---|
| 1 來源 | 公版原著＋版本／權利 | 自己寫的稿或自己整理的內容；引用別人的東西要標出處 |
| 2 翻譯 | `translate.py` | **不適用**：直接寫中文稿 |
| 3 審稿 | 對照原文 | 對照自己的資料核對事實、數字、人名；念出來順不順 |
| 4 說話者 | 分角色 | 大多是單人旁白；有引用某人說的話才標一個角色 |
| 5–8 | 同上 | 同上 |
| 輸出 | 影片兩版 | 影片＋純音訊檔 |

## 稿子格式
- `script/script.json`：`[{"id":"P001","en":"","zh_raw":"…","zh":"…"}, …]`；沒有原文時`en`留空字串，`zh_raw`和`zh`一樣
- 一段一個意思，句子短；寫給耳朵聽：少括號、少縮寫、數字寫成好念的樣子
- 停頓：段落之間自動停1.5秒；句子裡要更長的停頓用MiniMax的`<#秒數#>`標記
- `episode.json`：`intro`／`outro`寫自己的開場和結尾，`scenes`每段一張圖（圖放`art/paget/`，不一定是原刊插畫）
- 單人旁白：不要建`script/speakers.json`，`produce.py`會改走`tts.py`整段合成；要分角色才建（示範片只有一句福爾摩斯的話，所以`speakers.json`只有一行）
- 已經做完配音和畫面、只差組片時，把`status`設成`narrated`再跑`produce.py`，它就不會重畫畫面、也不會重打配音

## 純音訊（有聲書／Podcast用）
影片的AAC聲軌就是交付音質（本專案目標−14 LUFS、真峰值≤−1.0 dBTP），直接抽出來不重新編碼：
```bash
ffmpeg -i <集>/<NN-…-preview.mp4> -vn -c:a copy <輸出>.m4a
```
- 要MP3再轉：`ffmpeg -i <輸出>.m4a -c:a libmp3lame -b:a 192k <輸出>.mp3`（多一次有損編碼）
- 這只是「可以聽的音檔」；要上Podcast平台還需要RSS與平台帳號，這個skill沒有做，不能說成已上架

## 片頭卡（已知限制）
`art.py`的`title_card`固定寫「故事改編自<作者>公版原著」和「第N夜」，自己的主題用不上：畫完畫面後，另外重畫`art/frames/title.png`（同樣的字型與版面、照實寫來源），再組片。2026-11-17的示範片就是另外寫一支小程式，用`art.py`自己的`font`／`centered`重畫片頭卡

## 說明圖不要被照片調色壓暗
`art.py`會把每張圖都轉成暗棕色（給照片和舊插畫用）。說明圖、表格這類「重點在字和數字」的圖，轉完會幾乎看不清：畫完畫面後，把這幾張的`art/frames/cue-*.png`用原圖原色重出（可以稍微調暗，但不要重新上色），並把內容放在畫面上方約y 830以內，留出燒字幕的位置（兩行字幕最高到約y 873）；照片照舊用`art.py`的調色

## 自己的主題要用自己的文案
`package.py`仍是小說頻道的文案模板，預設會寫福爾摩斯、華生、柯南·道爾與公版原著等說明；自己的中文稿不能直接沿用這些輸出

組片後，依自己的稿子另寫標題、內容說明和實際來源，並檢查`upload/`文案；不要把自有內容標成某位小說家的原著改編

這次流程教學片的說明以同一份Obsidian原稿為準，產出影片或音檔不代表已獲授權上傳

## 手機要看得到字幕
組片產出的字幕是可開關的軟字幕，手機播放器預設常常不顯示。要直接燒進畫面：
```bash
python3 extras/burn_subs.py <集>/<NN-…-preview.mp4> <集>/build/zh-Hant.srt <輸出>.mp4
```
（沿用`shorts.py`的字幕描邊與換行；會重新編碼一次畫面，算重運算）
